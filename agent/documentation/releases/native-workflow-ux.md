## Recorded validation

The [qualification receipts](native-workflow-evidence.json) list the executed UI cases and hash each original test count file. Linux Xvfb uses VS Code 1.141.0. macOS uses VS Code 1.146.0. The final installed wheel passed 262 of 265 backend cases on each supported Linux Python/Robot pair. The three platform or prerequisite cases passed separately: two process-group checks on Darwin and a launch without Robot Framework. This included prepared attach, restart and real Python child sessions.

A real Test Results run held the second test open while the first showed a green check, the second showed its running icon and the running test's INFO message was visible. On completion the failure carried a source link to the offending keyword on line 9. The log command returned that test's anchor and the report command returned the same run's report. In the debug session, restarting from either the Robot or the Python stop preserved the breakpoints. Linux rendered 53 editor frames, 52 Return Explorer frames and 38 loading-prefix frames in the typing stability scenario.

The direct RobotCode comparison used its installed extension. Its Testing run populated the native tree and executed in the selected project interpreter. Companion's owned mode now shows progress in the same Testing view and offers separate current-test and current-suite entry points. RobotCode and VS Code document source links, a call stack and variables for debugging. The Companion checks inspected those elements and used the Debug Console, step, continue, stop and restart controls on real sessions.

Independent review identified additional cases during qualification. A pinned keyword tree must still navigate after its first jump opens Python. A failed test must publish only one failure and a suite teardown may turn it into a skip. Finally, a BDD completion must resolve to the keyword Robot will execute. Both supported Robot versions select `Action` for `Given Action` when both local definitions exist. The fixes have targeted regressions for each case. The literal test-name collision was also run end to end. Each of `Same`, its duplicate, and `Same#2` produced its own expected result, individually and together on both Robot versions.

F2 exposed a separate problem in a workspace opened through a directory symlink. The Robot call and the Python file on disk changed, while the already-open Python editor still showed the old decorator. Rename now edits the existing buffer for the same physical file and rejects conflicting or stale buffers. The nine keyword browsing, insertion and rename tests passed on each workspace spelling with the original open-editor assertion.

The final Linux extension integration run passed 355 of 355 cases with both supported Robot interpreters present. A fresh offline VS Code installation loaded the packaged VSIX and its bundled wheel and resolved a call to the expected resource and declaration line. All 63 runtime files in the archive matched the checkout byte for byte. The local VSIX SHA-256 is `1647c23d5064ad90abd2ab3afbc5c5f7a3ea14c2e27a3d0ef52db9c0842f16d9`.

A debug restart used to truncate the Testing journal while the reader retained its previous offset. Each worker now appends events tagged with its output directory. VS Code gives the restarted tests a separate result and a working Stop action. Two isolated editor cases covered toolbar Restart and an in-session adapter restart. The first execution failed and logged its own INFO message. In the second execution the same test passed, the new INFO message appeared before completion, and Stop left the waiting test skipped. Integration tests covered two consecutive restarts and equal-sized journal segments on both Robot versions.

A resource and a library alias can also share one namespace and keyword. With both declaring `Check Value` in `watched`, Robot 7.3.2 and 7.5 reject `Given watched.Check Value` as ambiguous. Completion suppresses that qualified call and definition lookup returns both declarations. The unqualified `Given Check Value` resolves to the resource and remains available in completion and Keyword Explorer. The full ten-case editor suite passed. In the editor, F12 displayed both definitions for the qualified call and opened resource line 2 directly for the unqualified call.

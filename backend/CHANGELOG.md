# Backend changelog

## Unreleased

- Plain public top-level functions of a statically readable module library are now library keywords, as RF 7.5 makes them: `def ring_bell()` is `Ring Bell` (RF's `printable_name`) with its location, arguments and docstring, for definition, hover, completion, signature help, references, the import quick fix and diagnostics. One shared AST reading (`module_reading`) decides both the indexed keywords and the names a library may also expose. A literal `__all__` (by Python name, also for `@keyword` functions), `ROBOT_AUTO_KEYWORDS = False` and `@not_keyword` are honoured, so a name RF hides is now an `unknown-keyword` error; two libraries defining `ring_bell` (or one `@keyword("Ring Bell")`) now get the `ambiguity` warning and qualify fixes. Nothing is guessed: a name bound or used otherwise at module level (import, assignment, conditional definition, other decorator, `register(fn)`) only silences unknown-keyword errors, and a class/dynamic library, computed `__all__`/`ROBOT_AUTO_KEYWORDS`, `keyword(...)(fn)` at import time or `setattr`/`globals()`/`sys.modules` writes leave the module's keywords open. Same-library duplicates (`ring_bell` and `ringBell`) are not indexed. Argument counts are no longer checked for a library keyword under `Set Library Search Order`, or when another library may expose the name without indexing it. Known gaps: imported/assigned-name collisions are not reported as ambiguous; a library failing to import at run time still counts as defining its keywords. `test_lsp_diagnostics_live.py` now has 24 cases, each new fixture also run with RF 7.5.
- Added a `discovery` service (`robot-companion-backend discovery`, descriptor entry `services.discovery`) implementing Robot Companion's normalized discovery API v1 over stdio JSON-RPC with LSP framing: `initialize` advertises `robotCompanionDiscovery.version` 1 and `robotCompanion/discoverTests` returns the workspace's `.robot` file suites with their tests and UTF-16 ranges, so Test Explorer needs no RobotCode. Files are walked by RF's directory rules (`_`/`.` prefixes and `CVS` ignored, symbolic links not followed) and built with RF 7.5's own reader, parser and `TestSuite.from_model` with the `__init__.robot` test defaults; nothing is executed, and a `language:` line naming a Python module is reported instead of imported. Tests tagged `robot:exclude` (also through init `Test Tags`) are left out, as RF leaves them out. Test labels are the names RF runs, with variables of the file's own Variables section, static built-ins and RF's number variables resolved by RF's `replace_string`; other variables stay as written. Ranges count lines as LSP clients do, also where RF breaks lines at U+2028 or form feeds. Parsing errors keep the tests RF builds, unreadable files are omitted, and both are reported in an additive `errors` array and on stderr; a non-file, relative or `..` workspace URI returns -32602. Every request rereads the workspace. New required live suite `test_discovery_live.py` (9 cases) compares the result with `robot --dryrun` on the audit corpus plus a nested fixture and runs in the release harness. The test client gained an optional `env`; `FramedStream` an outgoing size bound per service (discovery replies up to 64 MiB); diagnostics recognise `__INIT__.robot` as an init file case-insensitively, as RF does. Verified with Python 3.13.7, Robot Framework 7.5, debugpy 1.8.22 and Robocop 9.1.0 (RobotCode absent). Next backend candidates: debug robustness, per-test result streaming.
- Variable references and rename follow loop-carried values: a use in a `FOR`/`WHILE` body (or `WHILE` condition, nested loops included) that assigns a local of the same name anywhere in the body is reached by that local on later iterations, so it is a reference of both that local and the definition visible at its line (such as the suite variable). Rename changes both definitions and all their uses together, so the renamed suite runs the same with RF 7.5 (MIS-359's `${MODE}=    IF    True    Catenate    ${MODE}-x` repro no longer fails after renaming); it is refused with `RequestFailed` and no edit when a built-in or a suite variable defined in several imported files reaches the loop use. Uses outside such loops, definition and hover are unchanged. `test_lsp_navigation_live.py` now has 13 cases.
- Added broader diagnostics (`diagnostics.py`), published on open/change with UTF-16 ranges on the offending cell: RF 7.5's own parsing and model errors (now including invalid section headers, parsed with RF's resource/init loaders where they apply) as errors, and deprecated syntax (singular headers, `[Return]`) as warnings, as RF reports it; a keyword call that resolves to nothing in the import-aware scope as an error naming the keyword (an AShadow.py-only keyword is unknown); an ambiguous call as a **warning** (was an error) naming each source; argument counts the resolved signature cannot accept as errors, with RF's dry-run resolver and message; and undefined `${variable}` uses in test/keyword bodies as warnings. Each rule skips what cannot be known statically (class/dynamic/unmodelled libraries, `Import Library`, `Set Library Search Order`, variable files, variable-setting Python code, embedded or `@{}`/`&{}` arguments), and variables set dynamically anywhere in the workspace (`Set Test/Suite/Global Variable` as calls, settings or `Run Keyword` arguments, `VAR scope=...`) are never reported. Import diagnostics now cover the import's name cell.
- Added `textDocument/codeAction` quick fixes, advertised as `codeActionProvider` (`quickfix`) for clients with CodeAction literal support: import the only workspace resource or library file that defines an unknown keyword (never a guess between several files), and qualify an ambiguous call with a library/resource name.
- Added `textDocument/formatting` with Robocop 9.1.0's default formatters (new optional `format` extra, pinned in `constraints.txt`), advertised as `documentFormattingProvider` only when Robocop 9.1.0 is importable. Formatting is line-based TextEdits, deterministic (workspace Robocop configuration is not read), idempotent and keeps `\r\n` line endings. `doctor` reports the formatter; the release runner installs the extra and records it in `release.json`.
- New required live suite `test_lsp_diagnostics_live.py` (15 cases) runs in the release harness. Verified with Python 3.13.7, Robot Framework 7.5, debugpy 1.8.22 and Robocop 9.1.0 (RobotCode absent). Next backend candidates: test discovery/results API, debug robustness, range formatting.
- Added `textDocument/references`, `textDocument/prepareRename`/`textDocument/rename`, `textDocument/documentSymbol` and `workspace/symbol` (`navigation.py`), advertised in `initialize` (`renameProvider` with `prepareProvider`). Keywords are identified by their resolved definition, so references to AuditLibrary.py's `Build Record` include `Audit.Build Record` and never AShadow.py, same-named own keywords or ambiguous calls. Variable references and rename stay in the variable's scope. Rename edits a `.robot`/`.resource` user keyword's definition and every resolved call, keeping library/resource and BDD prefixes; Python library and standard-library keywords, ambiguous targets, embedded-argument keywords and built-in variables are refused with an LSP `RequestFailed` error. Variable uses include `$name` in conditions, `${{ }}` and BuiltIn's evaluating keywords, and an argument's `name=` cells in calls passing it by name; escaped `\${name}` is literal. Variables nested in `${{ }}`, in a variable name (`${greeting_${lang}}`) and in item access are found with RF's own variable search, and an inline IF assignment is visible only after its branch runs (also for definition and hover). New names are validated (one cell, no control-structure marker), and prepareRename reports the same refusals as rename. Document symbols are hierarchical (variables, tests/tasks, keywords with argument/local children; flat for clients without hierarchy support); workspace symbols find tests and keywords in unopened files. The `initialize` workspace folders are scanned on every request, so `didChange` and files created/changed/deleted on disk are reflected without a restart. New required live suite `test_lsp_navigation_live.py` (12 cases) runs in the release harness. Verified with Python 3.13.7, Robot Framework 7.5 and debugpy 1.8.22 (RobotCode absent). Next backend candidates: formatting and code actions, broader diagnostics, test discovery/results, `Run Keyword` arguments and Python library keyword rename.
- Keyword cells of `[Setup]`, `[Teardown]`, `[Template]`, `Suite Setup`/`Teardown`, `Test`/`Task Setup`/`Teardown` and `Test Template` now resolve for definition and hover (and references/rename); `NONE` is no keyword.
- One English BDD prefix (`Given`, `When`, `Then`, `And`, `But`) is ignored when the full call name matches no keyword, as in RF, for definition, hover, signature help and the new requests.
- Hover on a Python library keyword without a return annotation (`def other(x):`) no longer shows a false `Returns None`; `-> None` still shows `Returns None`.
- Hover and definition on a typed variable definition cell (`${PORT: int}    8080`, `${n: int}=    Set Variable    1`) now find that variable, as for its later uses.
- Accepting a variable completion inside an extended-syntax name (`${rec|ord.name}`, `${rec|ord[0]}`) keeps the suffix: the edit replaces only the sigil and base name. Without a closing `}` nothing after the cursor is replaced.
- Signature help splits `name=value` with RF's own rule, so `=` inside a variable, item access or inline expression (`Multi Step    ${{1 == 1}}`) is a positional value, not `**options`.
- Added `textDocument/hover`, `textDocument/completion` and `textDocument/signatureHelp`, advertised in `initialize` (completion `resolveProvider: false`, no snippets). They share definition's import-aware resolution, so unimported libraries (AShadow.py) never contribute. Hover shows keyword origin, RF-formatted arguments, return annotation and documentation, and variable source plus only statically written values. Completion offers keywords in call cells with their origin and scoped variables after `${`, with UTF-16 edit ranges. Signature help tracks positional, `name=value`, varargs and kwargs arguments. Markdown is used only when the client asks for it; workspace documentation is escaped. New required live suite `test_lsp_features_live.py` (15 cases) runs in the release harness.
- Standard-library and implicit BuiltIn keywords are now indexed from RF's own libdoc (Remote and unimportable libraries excepted), so they resolve for definition, hover, completion and signature help, below custom libraries as in RF.
- Variables now also resolve to imported resources' Variables sections, embedded keyword arguments, `FOR` and `EXCEPT AS` variables; a `VAR` value no longer counts as a definition of the variables it refers to.
- The `lsp` service removes its cwd from `sys.path` at start, and standard-library indexing does so again, so neither RF itself (`robot.py`) nor optional imports (XML's `lxml`, Screenshot's `wx`) can execute a same-named workspace module when the server runs as `python -m`.
- A variable used in a call's arguments resolves to its definition before that call (`${x}=    Set Variable    ${x}`), for definition and hover.
- A Python library whose function header cannot be located becomes an import diagnostic instead of failing every request for the importing file.
- A module-name library's namespace is its full module name (`company.robot.Helpers.Keyword`), not the text before its last dot.
- A position on the empty line after a final line break is accepted instead of failing.
- Standard-library imports (`Library    Collections`, `OperatingSystem`, ...) no longer produce an error diagnostic; as in RF, they win over a sibling file of the same name. Other module-name libraries without a sibling file (`a.b.C` → `a/b/C.py`, open buffer or disk) get an Information diagnostic `Library not resolved in this version: <name>`. Missing `.py`/path imports remain errors.
- LSP error replies carry the plain message instead of the `(code, message)` tuple repr.
- `scripts/build_dists.py` writes no `__pycache__` into the source checkout; the README's direct pip build sets `PYTHONDONTWRITEBYTECODE=1` for the same reason.

## 0.1.0.dev1 — phase-1 vertical slice

- Ran the live LSP, Robot DAP and mixed Robot/debugpy suites against the approved offline runtime (Python 3.13.7, RF 7.5, debugpy 1.8.22, RobotCode absent).
- Fixed the Robot worker: `run_cli` takes no listener instance, so the worker now parses the CLI with RF's public parser and adds its in-process listener before executing.
- Fixed Python child connection loss: a failing final flush of the lost socket no longer aborts cleanup, so `terminated` and the session `end` event are still sent.
- Repinned debugpy to the approved 1.8.22 (was 1.8.17, which the approved wheel set does not contain).
- Replaced the setuptools build with a dependency-free, reproducible in-tree PEP 517 backend and a minimal frontend; the release runner requires pip's rebuild from the sdist to be byte-identical. `doctor` no longer reports build tools as runtime requirements.
- Added bounded stdio framing, an explicit runtime probe and a standalone Python distribution definition.
- Added the LSP for parser/import-based navigation, current document overlays and limited syntax/import/ambiguity diagnostics.
- Added a `dap` service: a stdio DAP lifecycle subset with one owned Robot worker process group, an explicit RF prerequisite error, recorded unverified breakpoints and terminate/disconnect cleanup.
- Added the paused-thread RF listener for breakpoint verification, stack/scopes/variables, continue/next/stepIn and live Robot keyword console calls, with a required real-process DAP suite.
- Fixed private pipe cleanup when a worker fails to spawn; lifecycle checks cover real failed launches and reject unavailable Linux process observation.
- Added Python handoff v1 with an owned debugpy adapter, loopback child DAP connection, same-worker attachment and mixed-session cleanup, with six real-process conformance cases.
- Added an offline standalone build/install and conformance runner with source/hash/count receipts, isolated frontend-free venv execution and bounded owned-process cleanup.
- Copied the synthetic v1 audit corpus and added real-subprocess transport and language conformance drivers.

Exact-SHA release results are recorded in the issue `artifact-handoff`, not here.

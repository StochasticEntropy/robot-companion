    Referenz.

    Alles, was die Erweiterung tut, und was jeder Teil davon von deinem Projekt braucht.

    Die Übersicht führt die Argumente. Diese Seite ist die Bestandsaufnahme: jede Fähigkeit, genannt samt ihren tatsächlichen Grenzen, dazu die Voraussetzungen, die darüber entscheiden, ob die Hälfte dieser Erweiterung in deinem Workspace überhaupt etwas tut. Wo das Verhalten enger ist, als der Name vermuten lässt, steht das hier, statt dass du es selbst herausfinden musst.

    01Dokumentation schreiben

    Text, der neben dem Schritt steht, den er beschreibt

    Ein [Documentation]-Block sammelt die gesamte Erklärung am Anfang eines Tests, während die Schritte, die er beschreibt, fünfzig Zeilen weiter unten stehen. Beides driftet auseinander, und der Block wird zu dem, was niemand mehr pflegt. Die Alternative hier ist ein Kommentar-Marker: #> am Anfang eines Kommentars macht ihn zu Dokumentation, und er darf direkt über dem Schritt stehen, um den es geht.

    checkout.robotMarker gesetzt
    Guest Checkout Completes
    #> ## Guest checkout
    #> A shopper without an account completes an order.
    #>> The basket is prepared first, so the totals are known
    #>> before payment is attempted.
    ${basket}=    Add Item To Basket    SKU-4417
    #> -> the shop must accept the card and return a confirmation
    ${order}=     Place Order    ${basket}    shipping=EXPRESS
    • Verschachtelung. #>> und #>>> rücken in der gerenderten Ausgabe je Ebene um zwei Leerzeichen ein. Die Tiefe ist schlicht die Anzahl der >-Zeichen.
    • Beide Formen verschmelzen. Inline-Marker und ein klassischer [Documentation]-Block desselben Tests werden als ein einziges Dokument gerendert; Marker einzuführen bedeutet also nicht, das Vorhandene neu zu schreiben.
    • Umbrüche aus dem Quelltext verschwinden. Ein Satz, der über mehrere Kommentarzeilen verteilt ist, um deine Zeilenlänge einzuhalten, wird wieder zu Fließtext zusammengefügt. Ein ausdrückliches <br> bleibt als echter Umbruch erhalten, und mit Fences abgegrenzte Code-Blöcke bleiben exakt so, wie sie geschrieben sind.
    • Pfeilnotizen. Zeilen, die mit -> oder => beginnen, werden mit dem Marker in einer festen Spalte gerendert, der Text fließt daneben; eine umbrochene Erwartung hängt dadurch korrekt ein, statt wieder unter den Pfeil zu rutschen. Wiederholte Pfeile verschachteln um je eine Ebene.
    • Geltungsbereich. Durchsucht werden nur *** Test Cases ***, *** Tasks *** und *** Keywords ***. Settings- und Variables-Abschnitte werden ignoriert.
    02Das Panel

    Ein gerendertes Dokument, das zugleich ein Inhaltsverzeichnis ist

    Die Seitenleiste rendert den Block, in dem dein Cursor steht, als Markdown. Was daraus ein Werkzeug statt eines Betrachters macht, ist, dass der gerenderte Text die Navigation ist: jede Zeile führt per Klick genau auf die Quellzeile zurück, aus der sie stammt, du liest den Test also als Text und springst an der Stelle hinein, die dich interessiert.

    Diese Bindung ist nicht positionsbasiert. Frühere Versionen ordneten gerenderte Zeilen den Quellzeilen der Reihe nach zu; das brach, sobald der Markdown-Renderer die Ausgabe umgruppierte, und spätere Links landeten auf den falschen Zeilen. Jeder Eintrag trägt jetzt einen ausdrücklichen Marker, der im gerenderten Markdown eingebettet ist, sodass die Bindung überlebt, was immer der Renderer mit der Form anstellt.

    • Variablen, aufgelistet. Jedes lokale VAR und jedes Set Variable im Block erscheint in einem Variables-Abschnitt, jeweils verlinkt auf die Zeile, die es definiert. Variablen, die aus Keyword-Aufrufen zugewiesen werden, bekommen ihren eigenen, einklappbaren Returned Variables-Abschnitt.
    • Werte werden in den Text eingesetzt. Dokumentation, in der „die Summe ist ${Total}“ steht, wird mit dem tatsächlichen Wert gerendert — aber nur, wenn er eindeutig ist. Eine Variable mit mehreren verschiedenen Zuweisungen oder eine, die von einem Zweig abhängt, bleibt als wörtliches Token stehen, statt einen Wert zu wählen und selbstbewusst falsch zu liegen.
    • Eine Übersicht der Datei. Jeder dokumentierte Block aufgelistet, mit einem Filter Show keywords, der nur erscheint, wenn die Datei tatsächlich dokumentierte Keywords enthält.
    • Eine CodeLens über jedem Dokumentationsblock öffnet die Vorschau. Standardmäßig an, abschaltbar über enableCodeLens.
    • Eine optionale Hover-Vorschau des gesamten Blocks. Das ist die eine Funktion, die standardmäßig bewusst aus ist — es ist ein großer Hover, und er sollte etwas sein, das du ausdrücklich anforderst.
    03Farbe

    Eine Zeile als Warnung markieren, statt nur „Warnung“ zu schreiben

    Dokumentation unterstützt eine kleine Menge von Tags, in der Live-Vorschau und in beiden Exportformaten. Diese Tags sind zuerst semantisch gemeint; einfache Farben stehen daneben bereit, wenn du schlicht eine Farbe willst.

    • <note> Hintergrund
    • <question> offener Punkt
    • <warning> Risiko
    • <error> bekannte Abweichung
    • <success> bestätigt

    Acht Farbkürzel — <red>, <orange>, <yellow>, <green>, <blue>, <pink>, <purple>, <gray> — stehen daneben, und <color value="#0f766e"> nimmt einen beliebigen Wert.

    Alles andere ist Text. Eine nicht unterstützte Farbe, ein unerwartetes Attribut oder beliebiges HTML wird maskiert und als schlichte Zeichen gerendert statt interpretiert. Das ist eine bewusste Zusage, und sie ist durch einen Test festgehalten, der dem Renderer Markup vorlegt, das auf Ausführung angelegt ist, und prüft, dass es als sichtbarer Text herauskommt.

    04Weitergeben

    Die Dokumentation war immer schon weitergabefähig

    Eine gerenderte Testbeschreibung nützt Leuten, die deinen Editor nie öffnen werden — jemandem, der ein Release freigibt, jemandem, der fragt, was eine Suite eigentlich abdeckt. Vier Befehle exportieren den aktuellen Block oder eine Mehrfachauswahl von Blöcken, mit eingesetzten Variablen und Seitenumbrüchen zwischen den Test Cases.

    • Markdown schreibt eine echte Datei, über einen Speichern-Dialog — nirgends wird etwas geschrieben, bevor du einen Pfad wählst. Die für Autoren gedachten Farb-Tags bleiben erhalten, die exportierte Datei bleibt also in demselben Vokabular editierbar, in dem du geschrieben hast.
    • Druckfertiges HTML ist das, was die „PDF“-Befehle tatsächlich erzeugen. Die Erweiterung hat keinen PDF-Writer: Sie rendert eine für den Druck gestaltete Seite mit fest eingestelltem hellem Theme, schreibt sie in eine temporäre Datei und öffnet sie in deinem Browser, wo du nach PDF druckst. Daneben gibt es eine zweite Schaltfläche, die den Druck von VS Code selbst versucht. Es lohnt sich zu wissen, dass das der Mechanismus ist — das Ergebnis ist ein PDF, aber dein Browser erzeugt es.
    05Was zurückkommt

    Die Frage, die dich drei geöffnete Dateien kostet

    Ein Keyword gibt ein Objekt zurück. Dessen Felder sind in einer Python-Klasse deklariert, die die meisten davon von einer Basisklasse in einem anderen Modul erbt, das unter einem Alias importiert wird. Die Frage „was kann ich hier ablesen“ von Hand zu beantworten heißt, alle diese Dateien zu öffnen. Der Return Explorer beantwortet sie neben dem Cursor, in der einzigen Form, die wirklich nützt — als Zeichenkette, die du einfügen kannst.

    Robot Return Explorerworauf du zugreifen kannst
    ${order.confirmation_number}
${order.status}
${order.shipping.method}
${order.items[0].name}
${order.items[0].line_total}

    Die erste Fassung dieses Panels zeigte einen Typbaum. Innerhalb von zwei Tagen wurde sie umgeschrieben und zeigt stattdessen Zugriffspfade, denn wer Tests schreibt, will keinen Typ durchblättern — er will den Ausdruck. Der Baum lebt darunter als Technical Details weiter, für die Fälle, in denen du ihn doch willst.

    • Vererbung. Felder, die auf Basisklassen deklariert sind, werden aufgelöst, auch zwei gleichnamige Basisklassen in verschiedenen Modulen, verfolgt über import … as …-Aliase. Einer Basis wird nur gefolgt, wenn sie wie ein strukturierter Typ aussieht; die Vererbung von einem einfachen Mixin wird übersprungen.
    • Generics. list[T], Wrapper[T] und Optional[list[T]] werden zum Elementtyp aufgelöst, gesteuert von einer Richtlinie, die du auf immer, nie oder eine ausdrückliche Erlaubnis- bzw. Sperrliste von Containern setzen kannst.
    • Indizierter Zugriff. Ein Feld mit Collection-Typ liefert ${order.items[0].name}, wobei der Index in jeder Tiefe auf dem richtigen Segment landet — denn sonst ist der Pfad falsch, und ein falscher Pfad ist schlimmer als gar keiner.
    • Properties. @property-Getter werden neben einfachen Feldern als Member indiziert.
    • Geparst wird textuell, nicht über einen AST. Attribute, die nur innerhalb von __init__ zugewiesen oder dynamisch eingefügt werden, sind unsichtbar. Das ist ein bewusster Tausch: Um diese Fragen zu beantworten, wird nichts aus deinem Workspace importiert oder ausgeführt.

    Zwei Schreibweisen desselben Feldes. Manche Projekte geben ihren Modellklassen eine Basis, die jedes snake_case-Attribut zusätzlich in camelCase lesbar macht. Wo das zutrifft, wählt returnFieldNameStyle, welche Schreibweise die Zugriffspfade verwenden — camelCase, roh oder beide. Ableiten lässt es sich nicht, also wird es deklariert: camelCaseAliasBaseNames führt die Namen der Basisklassen auf, die einen Typ als konvertierend kennzeichnen; abgeglichen wird als Teilzeichenkette gegen die gesamte Vererbungskette, ohne Rücksicht auf Groß- und Kleinschreibung, Unterstriche und Bindestriche. Der Standardwert ist ["camelcase"], eine Basis namens CamelCaseBase funktioniert also unverändert; trag deine eigene Marker-Klasse in die Liste ein oder leere sie, um das Aliasing abzuschalten. Typen ohne eine solche Basis geben immer genau die Attributnamen wieder, die in Python geschrieben stehen.

    06Argumente

    Was dieses Argument annimmt, und welcher Wert gerade hineinfließt

    Ein Hover über einem benannten Argument zeigt die Member des Enums, das es annimmt, wobei der gerade übergebene Wert markiert und auf die Zeile verlinkt ist, die ihn zugewiesen hat. Diese zweite Hälfte ist die nützliche: Wenn ein Test fehlschlägt, lautet die Frage selten „was ist erlaubt“ und meistens „was ist tatsächlich angekommen, und woher stammt es“.

    • Die Herkunft wird ausgewiesen. Ein Treffer wird als direct, argument-fallback oder annotation-only gekennzeichnet, bei den beiden lockereren mit einem Hinweis auf die Verlässlichkeit. Das lockere, namensbasierte Fallback gibt es, es ist aber standardmäßig aus — es wurde eine Version nach seiner Einführung abgeschaltet, weil eine selbstbewusst falsche Antwort schlimmer ist als keine Antwort.
    • Duplikate fallen zusammen. Dasselbe Enum, in mehreren Modulen mit identischen Membern definiert, wird einmal gerendert, mit einem Hinweis darauf, wie viele zusammengefasst wurden.
    • Hinweise wandern durch Wrapper. Ein .resource-Keyword, das ein Argument an ein weiteres Keyword durchreicht, welches am Ende bei einem typisierten Python-Keyword ankommt, erbt den Hinweis, über bis zu zwölf Glieder der Weiterleitung hinweg. Suites, die als dünne Robot-Schicht über Python gebaut sind, bekommen so Wissen über Argumente, das sie selbst nie annotiert haben.
    • Docstrings werden gerendert. Args, Returns und Raises im Google-Stil werden normalisiert. Lässt sich ein Docstring nicht parsen, bekommst du ein Warnbanner und den Inhalt — gar nicht zu rendern ist schlimmer, als unvollkommen zu rendern.
    • Insert schreibt das Argument für dich. Ein Args-Eintrag für ein Argument, das in deinem Aufruf fehlt, bietet einen Link an, der ...    name= als ausgerichtete Fortsetzungszeile einfügt, den Cursor hinter das = setzt und die Vorschläge öffnet. Die dokumentierte Reihenfolge der Argumente wird eingehalten, und ein Klick auf ein bereits vorhandenes Argument fokussiert es, statt ein Duplikat hinzuzufügen.
    07Variablen

    Der eine Teil, der überhaupt kein Python braucht

    Ein Hover über einer Variablen zeigt ihren Wert, aufgelöst aus Set Variable oder einem VAR aus Robot Framework 7, einschließlich typisierter Namen wie ${name: date}. Alias-Ketten werden verfolgt. Eine Variable, die in einer längeren Zeichenkette eingebettet ist, wird zu dem Token aufgelöst, in dem dein Cursor tatsächlich steht.

    Der interessante Fall ist eine Variable, die in mehr als einem Zweig zugewiesen wird:

    eine Variable mit zwei ZukünftenIF / ELSE
    IF    ${express}
    VAR    ${carrier}    OVERNIGHT
ELSE
    VAR    ${carrier}    STANDARD
END

    Ein Hover über ${carrier} zeigt beide Kandidaten, denn die Zweige schließen einander aus, und sie auf einen zu reduzieren wäre eine selbstbewusste Lüge. Jeder Kandidat ist einzeln anklickbar und führt zurück zu seiner Zuweisung.

    Eine Grenze, die man kennen sollte. Zweige entstehen nur durch IF / ELSE IF / ELSE. Zuweisungen in FOR-, WHILE- oder TRY-Körpern werden nicht nach Zweigen unterschieden — diese Blöcke werden nur mitgeführt, damit ein verirrtes END den Parser nicht durcheinanderbringt.

    08Completions

    Drei Arten, an acht Trigger-Zeichen

    • Enum-Werte nach argname=. Eine Einstellung bestimmt, ob dabei der Name des Members, der wörtliche Wert oder beides eingefügt wird. Übersprungen, wenn das, was du getippt hast, bereits wie eine Variablenreferenz aussieht.
    • Lokale Variablen mit passendem Typ. Tippst du orderData=, werden die Variablen dieses Tests angeboten, die aus einem Keyword mit passendem Rückgabetyp zugewiesen wurden. Absichtlich nur eventually consistent: Bei kaltem Cache liefert der erste Trigger sie noch nicht, sondern stößt die Arbeit an, sodass sie beim nächsten erscheinen.
    • Member einer Rückgabevariablen nach ${order., bis zu einer konfigurierbaren Tiefe, inklusive der automatisch geschlossenen }. Bei Feldern mit Collection-Typ wird [0] für dich eingefügt. Der Präfixabgleich akzeptiert beide Schreibweisen — status_ zu tippen trifft weiterhin statusCode.
    09Folding

    Auf die Form der Dokumentation zusammenklappen

    Dokumentations-Marker wirken als Abschnittsgrenzen, ein langer Test klappt also auf seine eigene Gliederung zusammen. Eine Überschrift besitzt alles bis zur nächsten Überschrift gleicher oder höherer Ebene; ein #> endet beim nächsten Marker derselben Tiefe; verschachtelte Marker klappen unabhängig voneinander. Zwei Befehle — Fold to Headlines und Fold to Steps — dazu Unfold, verfügbar über die Palette und über die Vorschau.

    Ein Befehl ändert deine Einstellungen. Use Robot Companion as Default Folding Provider schreibt editor.foldingStrategy und editor.defaultFoldingRangeProvider in dein Sprach-Override [robotframework] — im Workspace-Bereich, wenn ein Workspace geöffnet ist, sonst global. Es gibt ihn, weil konkurrierende Folding-Provider sonst zu etwas verschmelzen, das keiner von beiden beabsichtigt hat.

    10Voraussetzungen

    Was die Erweiterung von deinem Projekt braucht

    Die Abschnitte 05, 06 und 08 lesen alle denselben Python-Index. Passt dein Projekt nicht zu diesen Annahmen, scheitern diese Funktionen nicht lautstark — sie finden still nichts. Das ist der Teil, den zu lesen sich am meisten lohnt, bevor du entscheidest, dass die Erweiterung nicht funktioniert.

    Es brauchtSonst
    Python-Keywords, dekoriert mit @keyword(...), mit Klammern Eine schlichte Methode, die Robot Framework bereitwillig als Keyword bereitstellt, ist hier unsichtbar. Jede aus Python abgeleitete Funktion — Argumenthinweise, Annotationen, Rückgabetypen, Docstrings, Insert — wird ausschließlich aus der dekorierten Liste gebaut.
    Keyword-.robot-Dateien unter einem Pfad, der auf *keywords* passt Diese werden übersprungen. .resource-Dateien werden von überall indiziert, das trifft also nur Projekte, die Keywords in .robot-Dateien außerhalb eines solchen Ordners definieren.
    indexExcludeFolderPatterns durchgesehen Standardmäßig schließt es tests aus — ein sehr verbreitetes Zuhause für Robot-Suites und ihre Ressourcen.
    Rückgabetypen, die strukturierte Klassen sind Bei einem Keyword, das ein Dict oder ein untypisiertes Objekt zurückgibt, gibt es nichts aufzulösen.

    indexImportFolderPatterns auf die Ordner einzugrenzen, in denen deine Keyword-Bibliotheken tatsächlich liegen — ["libs/**"] statt ["**"] —, ist der größte einzelne Hebel, wenn das Indizieren in einem großen Repository langsam wirkt.

    11Geschwindigkeit

    Beim Tippen nicht im Weg stehen

    Rückgabetypen aufzulösen ist echte Arbeit — Typen durch Importe und Vererbung zu verfolgen — und auf dem Haupt-Thread des Editors erledigt, macht sie das Tippen unangenehm. Diese Arbeit läuft in einem Worker-Thread, der überhaupt keinen Zugriff auf das Dateisystem hat; er bekommt einen Snapshot und rechnet. Ergebnisse werden im Speicher gecacht und pro Workspace auf der Platte abgelegt.

    • Ein Ergebnis bedient jede Variable eines Typs. Zugriffspfade werden als variablenunabhängige Vorlage berechnet und beim Lesen an deinen tatsächlichen Variablennamen gebunden.
    • Das Speichern einer Python-Datei aktualisiert nur den Beitrag dieser Datei, abhängige Cache-Einträge werden verworfen. Früher wurde dabei der Workspace neu durchsucht.
    • Das Vorwärmen im Hintergrund tritt hinter dich zurück. Jeder Hover und jede Completion markiert dich als aktiv; das Vorwärmen bricht mitten im Lauf ab und wartet auf eine Pause.
    • Hovers lesen zuerst den Cache und lassen dann ein Zeitfenster von 45 ms verstreichen, bevor die teure Arbeit beginnt — ein Hover, von dem du schon weitergezogen bist, kostet dich diesen Aufwand also nie.
    • Während einer Robot-Debug-Sitzung bleiben die passiven Funktionen aktiv — Hover, Completions, Folding-Bereiche, beide Panels und Insert. Ausgesetzt wird nur, was unter einem laufenden Debugger Text verschiebt. Eine frühere pauschale Pause machte das Werkzeug genau dann unbrauchbar, wenn man es am dringendsten wollte.

    Wenn die Auflösung der Rückgabetypen nicht mehr antwortet, hat sich der Worker beendet: Er startet nicht neu und bleibt für den Rest der Sitzung still. Invalidate All Caches und ein Neuladen des Fensters holen ihn zurück, und der Ausgabekanal Robot Companion sagt, was passiert ist.

    14Grenzen

    Wo es aufhört

    • Die Erweiterung ist additiv, mit zwei Ausnahmen. Sie registriert weder einen Formatter noch Diagnostics und kommt deshalb mit anderem Robot-Tooling aus. Die beiden Dinge, die tatsächlich schreiben, sind Insert, das deinen Test bearbeitet, und der Befehl für den Default-Folding-Provider, der deine Einstellungen bearbeitet. Der Export schreibt nur dorthin, wohin du einen Speichern-Dialog lenkst.
    • Python wird gelesen, nie ausgeführt. Typen werden durch das Lesen von Quelltext gewonnen. Es wird nichts importiert, also führt nichts in deinem Workspace etwas aus — und dynamisch konstruierte Attribute sind dadurch unsichtbar.
    • Der technische Baum hat feste Obergrenzen, die deine Einstellungen nicht anheben: fünfzehn Enum-Member pro Typ, zwei verschachtelte Typen pro Feld, fünf geerbte Basisklassen.
    • Ein paar Feldnamen bleiben immer verborgen, und zwar in der einfachen Zugriffsliste — Namen aus der Container-Mechanik, die nie das sind, worauf du prüfen wolltest.
    • Das Rendern von Keyword-Dokumentation ist Best Effort. Bei mehrdeutigen Treffern wird der beste gezeigt, dazu die Alternativen; nicht parsebare Docstrings warnen und werden trotzdem gerendert.
    • Es ist eine lokale Erweiterung. Sie funktioniert über Remote SSH und Dev Containers, aber jede Datei, die sie liest, geht über die Remote-Brücke, das Indizieren eines großen entfernten Workspace ist deshalb langsamer.

    Wie viel davon getestet ist. npm run test:all führt dreiundzwanzig Node-Testgruppen aus, dazu drei Suites, die einen echten VS Code Extension Development Host steuern — sie klicken jedes gerenderte Vorschauziel über die tatsächliche Webview-Brücke an und prüfen, wo der Cursor landet, und sie prüfen nach dem Einfügen eines Arguments den genauen resultierenden Zeilentext und die Cursorposition. Die Arbeit am Folding hat das verdient: Tests auf Parser-Ebene liefen weiter durch, während die Funktion in einem echten Fenster sichtbar kaputt war.
